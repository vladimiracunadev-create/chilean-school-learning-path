### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé cómo funciona una aplicación web, qué hace cada parte y qué cuidados exigen los datos de las personas que la usan.

**Lo que ya debo saber.** Sé usar un navegador. Sé qué es un dato personal. Sé qué es un requerimiento.

**Explicación.**

Una aplicación web funciona entre dos partes. El cliente es el navegador de la persona, que muestra la página; el servidor es el computador de la empresa que guarda la página y los datos y responde a los pedidos. Una página se arma con HTML (la estructura y el contenido), CSS (la presentación: colores y tamaños) y JavaScript (el comportamiento: reacciona a clics y valida formularios).

Para que la gente vea el sitio hay que publicarlo: se contrata un hosting (servicio que guarda el sitio y lo mantiene disponible) y un dominio (el nombre con que se encuentra, como un nombre de ejemplo «panaderia-ejemplo.cl»). Un sitio seguro usa HTTPS, que cifra la comunicación entre el navegador y el servidor para que nadie pueda leer los datos en el camino.

Un formulario recoge datos personales, así que exige cuidado: se piden solo los datos necesarios, se informa para qué se usan y se actúa según la norma vigente de protección de datos. Las imágenes y textos del sitio deben ser propios o tener permiso. El sitio debe poder usarse por todas las personas: textos legibles y descripciones de las imágenes.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| cliente | navegador de la persona que muestra la página |
| servidor | computador que guarda la página y responde pedidos |
| HTML | lenguaje que da estructura y contenido a la página |
| CSS | lenguaje que define la presentación de la página |
| JavaScript | lenguaje que da comportamiento a la página |
| hosting | servicio que mantiene el sitio disponible |
| HTTPS | comunicación cifrada entre navegador y servidor |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Quién hace qué*

Problema: Una página de ejemplo cambia el color del título. ¿Qué lenguaje se encarga de la presentación?

1. El color es parte de la presentación.
2. La presentación la define CSS.

Respuesta: CSS

*Ejemplo 2. Datos necesarios*

Problema: Un formulario de ejemplo pide nombre, teléfono, dirección y color favorito para entregar un pedido. ¿Cuál dato sobra?

1. Para entregar se necesita saber a quién y dónde.
2. El color favorito no es necesario.

Respuesta: El color favorito

**Errores frecuentes y cómo reconocerlos**

- **Error:** Pedir en el formulario todos los datos posibles «por si sirven». **Por qué ocurre:** Se recogen datos personales sin necesidad y aumenta el riesgo. **Cómo corregirlo:** Pide solo lo necesario y avisa para qué se usa.
- **Error:** Usar fotos descargadas de cualquier sitio sin permiso. **Por qué ocurre:** Las imágenes pueden tener derechos de autor. **Cómo corregirlo:** Usa fotos propias o con permiso claro de uso.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé las etiquetas básicas de HTML, los documentos de un proyecto web y los roles del equipo.

**Lo que ya debo saber.** Sé qué hacen HTML, CSS y JavaScript. Sé qué es un servidor y un navegador. Sé qué es un dato personal.

**Explicación.**

HTML usa etiquetas que se abren y se cierran. <h1> es un título principal, <p> un párrafo, <a href> un enlace a otra página, <img src alt> una imagen con su descripción alternativa, <form> un formulario, <input> un campo para escribir y <button> un botón. CSS usa reglas con un selector (a quién se aplica, como h1) y propiedades entre llaves (qué cambia, como color).

Un sitio se planifica con documentos. El mapa del sitio lista las páginas y sus enlaces; la maqueta es el dibujo de cómo se verá cada página; el documento de requisitos dice qué contenidos hacen falta, y la política de privacidad explica qué datos se recogen, para qué y por cuánto tiempo. Estos documentos permiten revisar el trabajo antes de programar.

Los roles reparten el trabajo: la diseñadora crea la maqueta, el desarrollador escribe el código, la administradora publica y mantiene el sitio y la dueña aprueba el contenido. Cuando algo del sitio falla, un enlace que no funciona devuelve el código 404 (página no encontrada) y un fallo del servidor devuelve el código 500; el código 200 significa que todo salió bien.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| etiqueta | marca de HTML que indica qué es cada parte de la página |
| enlace | texto que lleva a otra página (<a href>) |
| alt | descripción escrita de una imagen |
| selector (CSS) | parte de la regla que dice a qué elemento se aplica |
| mapa del sitio | lista de páginas y cómo se enlazan |
| maqueta | dibujo de cómo se verá cada página |
| código 404 | respuesta «página no encontrada» |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Leer una etiqueta*

1. El texto visible es Escríbenos.

*Ejemplo 2. Leer una regla CSS*

Respuesta: A los párrafos; su color pasa a rojo

**Errores frecuentes y cómo reconocerlos**

- **Error:** Escribir una imagen sin el atributo alt. **Por qué ocurre:** Una persona con lector de pantalla no sabe qué muestra la imagen. **Cómo corregirlo:** Escribe una descripción breve en alt.
- **Error:** Dejar enlaces que llevan a páginas que no existen. **Por qué ocurre:** El navegador mostrará el error 404 y la persona se frustra. **Cómo corregirlo:** Revisa todos los enlaces con el mapa del sitio.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a seguir a mano la validación de un formulario web y a decidir qué respuesta recibe cada persona.

**Lo que ya debo saber.** Sé qué es un formulario HTML. Sé hacer la traza de un condicional. Sé qué es validar un dato.

**Explicación.**

Validar un formulario es revisar los datos antes de aceptarlos. En el navegador, JavaScript puede hacerlo apenas la persona envía, y muestra un mensaje claro si algo está mal, sin perder lo que escribió. Una función de validación recibe los datos y devuelve un resultado; el primer if que se cumple termina la función con su return, y los demás no se evalúan.

Para razonar a mano se prueban casos de ejemplo uno por uno: se evalúan las condiciones en el orden en que están escritas y se anota el resultado. Los casos límite (14 y 20 en la edad) son los más importantes, porque ahí se cometen más errores. Los operadores && (y), || (o: basta que una se cumpla) y ! (no) permiten combinar condiciones.

La validación en el navegador ayuda a la persona, pero no basta: cualquiera puede saltarse el navegador, así que el servidor debe volver a validar. Los mensajes de error no deben revelar datos de otros usuarios. Y los datos de personas menores de edad exigen especial cuidado: solo se piden los necesarios y se avisa a una persona adulta responsable cuando corresponde.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| validación | revisión de los datos antes de aceptarlos |
| caso límite | valor justo en el borde de lo permitido |
| return | instrucción que termina la función entregando un resultado |
| && | operador «y»: ambas condiciones a la vez |
| ! | operador «no»: invierte la condición |
| validar en el servidor | volver a revisar los datos en el servidor aunque ya se hayan revisado en el navegador |

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a aplicar criterios técnicos con datos de ejemplo para decidir si un sitio está listo para publicarse, cuidando seguridad, privacidad y rendimiento.

**Lo que ya debo saber.** Sé qué hacen HTML, CSS y JavaScript. Sé qué es HTTPS y validar en el servidor. Sé calcular tiempos con división.

**Explicación.**

Publicar un sitio es una decisión técnica que se respalda con una lista de verificación. Se revisa la seguridad (HTTPS, contraseñas guardadas como hash, validación en el servidor), la privacidad (política visible y solo datos necesarios), los contenidos (permiso y alt en imágenes) y la continuidad (respaldo y enlaces sin errores). Si falta un elemento obligatorio, no se publica hasta corregirlo.

El rendimiento también importa: una página pesada tarda más en cargar, sobre todo en conexiones lentas. El peso de la página es la suma de sus archivos (imágenes, estilos y scripts) y el tiempo estimado de carga es el peso dividido por la velocidad. Reducir el tamaño de las imágenes es una mejora común.

Una regla de seguridad clave: nunca confiar en lo que escribe el usuario. Todo dato que llega por un formulario se valida y se trata como texto, no como instrucciones, para evitar que alguien manipule el sitio. Las contraseñas nunca se guardan escritas y en este cuaderno jamás se escriben contraseñas reales. El equipo anota la decisión y a quien la autorizó.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| lista de verificación | lista de comprobaciones antes de publicar |
| peso de la página | suma del tamaño de todos sus archivos |
| KB | kilobyte: unidad de tamaño de archivos |
| entrada no confiable | dato que llega del usuario y debe validarse |
| hash | resumen que se guarda en vez de la contraseña escrita |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Tiempo de carga*

Problema: Una página de ejemplo pesa 600 KB y la conexión es de 100 KB por segundo. ¿Cuánto tarda?

1. Tiempo = peso dividido por velocidad.
2. 600 ÷ 100.

Respuesta: 6 segundos

*Ejemplo 2. Decidir publicar*

Problema: En una lista de verificación de ejemplo falta HTTPS y todo lo demás está listo. ¿Se publica?

1. HTTPS protege los datos del formulario.
2. Es obligatorio: se corrige antes de publicar.

Respuesta: No, se corrige primero

**Errores frecuentes y cómo reconocerlos**

- **Error:** Publicar el sitio con un elemento obligatorio pendiente «para cumplir la fecha». **Por qué ocurre:** Los datos de las personas quedan expuestos. **Cómo corregirlo:** Informa a la jefatura y mueve la fecha.
- **Error:** Aceptar el texto del formulario sin revisar porque «solo escriben clientes». **Por qué ocurre:** Cualquiera puede enviar datos inesperados o dañinos. **Cómo corregirlo:** Trata toda entrada como no confiable y valídala.

**Solucionario razonado**

- **R1.** C) La suma del tamaño de todos sus archivos. El peso incluye imágenes, estilos y scripts.
- **R2.** B) No debe publicarse hasta corregirlo. Los obligatorios se cumplen antes de publicar.
- **R3.** C) Como entrada no confiable: se valida. Todo dato del usuario debe revisarse.
- **C1.** 1.400 KB. Se suman las tres imágenes, el estilo y el script. Cálculo: 3 × 400 + 50 + 150 = 1.400.
- **C2.** 7 segundos. El tiempo es el peso total dividido por la velocidad. Cálculo: (3 × 400 + 50 + 150) ÷ 200 = 7.
- **C3.** 500 KB. Cambia el peso de las tres imágenes; lo demás queda igual. Cálculo: 3 × 100 + 50 + 150 = 500.
- **A1.** 5 segundos. Se divide el nuevo peso por la velocidad de 100 KB por segundo. Cálculo: (3 × 100 + 50 + 150) ÷ 100 = 5.

- **Z2.** A) Usar una contraseña inventada de ejemplo. Las contraseñas reales no se escriben ni se piden en pruebas.

- **D2.** A) Derivar el pedido a quien administra los datos, según la norma vigente. Una persona puede consultar sus datos y el pedido se atiende por quien corresponde.
