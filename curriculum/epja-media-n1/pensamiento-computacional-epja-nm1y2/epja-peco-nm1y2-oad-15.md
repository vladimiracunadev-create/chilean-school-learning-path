### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Hoy aprenderé a pasar un algoritmo desde las palabras al seudocódigo y de ahí a un lenguaje de programación, Python, reconociendo qué instrucción corresponde a cuál.

**Lo que ya debo saber.** Ya uso listas, tablas y números en mi vida diaria, como una boleta, un horario o un registro de gastos. Sé que un algoritmo es una secuencia de pasos claros para resolver un problema.

**Explicación.**

Un lenguaje de programación es un conjunto de reglas escritas para dar instrucciones a una computadora. Sus reglas de escritura se llaman sintaxis. Python es uno de esos lenguajes. Hoy no usamos computador: leemos el código y lo seguimos a mano, como lo haría un intérprete, que es el programa que ejecuta el código.

El proceso lógico va en tres escalones: primero el problema en palabras, luego el seudocódigo, que ordena los pasos sin reglas estrictas, y por último el código. Cada símbolo tiene su equivalente: la flecha ← se escribe = en Python, el signo × se escribe *, y «mostrar» se escribe print( ). Los textos van entre comillas y una línea que empieza con # es un comentario que no se ejecuta.

Cuidado con dos símbolos parecidos: = guarda un valor en una variable y == compara si dos valores son iguales. Un entorno de programación es el lugar donde se escribe y se ejecuta el código. Escribir primero el seudocódigo ayuda a revisar la lógica antes de preocuparse por la sintaxis.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| lenguaje de programación | reglas escritas para dar instrucciones a una computadora |
| sintaxis | reglas de escritura de un lenguaje |
| comentario | línea con # que explica el código y no se ejecuta |
| entorno de programación | lugar donde se escribe y se ejecuta código |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Leer el código*

Problema: Con el código de la ficha, ¿qué muestra print(total)?

1. precio = 1500 y cantidad = 3.
2. total = precio * cantidad = 1500 × 3 = 4500.
3. print(total) muestra ese valor.

Respuesta: 4500

*Ejemplo 2. Traducir a Python*

Problema: Traduce a Python: «descuento ← 200; neto ← total − descuento; mostrar neto».

1. La flecha ← pasa a ser =.
2. El signo − se escribe -.
3. «Mostrar» pasa a ser print( ).

Respuesta: descuento = 200 / neto = total - descuento / print(neto)

**Errores frecuentes y cómo reconocerlos**

- **Error:** Escribir 3 = cantidad, con el valor a la izquierda. **Por qué ocurre:** En Python el nombre de la variable va a la izquierda del =. **Cómo corregirlo:** Escribe cantidad = 3.
- **Error:** Usar == para guardar un valor, como «total == precio * cantidad». **Por qué ocurre:** == compara; no guarda nada. **Cómo corregirlo:** Para guardar usa un solo =.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Hoy practicaré cómo traducir repeticiones y decisiones del seudocódigo a Python y cómo seguirlas a mano, distinguiendo errores de sintaxis y errores de lógica.

**Lo que ya debo saber.** Ya uso listas, tablas y números en mi vida diaria, como una boleta, un horario o un registro de gastos. Sé que un algoritmo es una secuencia de pasos claros para resolver un problema.

**Explicación.**

Las repeticiones y las decisiones tienen su palabra en Python. «Mientras» se escribe while, «si» se escribe if y «si no» se escribe else. Después de la condición se escriben dos puntos. Las líneas que se repiten o que dependen de la condición van con sangría, es decir, corridas hacia la derecha.

También hay operadores de comparación: >, <, >=, <= y ==. Además, % entrega el resto de una división: 8 % 2 es 0 porque 8 se divide exacto entre 2. Para seguir el código a mano, haz una tabla de seguimiento con el valor de cada variable y lo que se muestra.

Hay dos clases de error. Un error de sintaxis rompe las reglas de escritura, como olvidar los dos puntos: el lenguaje no entiende la instrucción. Un error de lógica sí se entiende, pero hace algo distinto de lo que querías, como escribir > donde debía ir >=. Para encontrarlo, hay que probar casos.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| while | palabra de Python que repite mientras una condición sea verdadera |
| if / else | palabras de Python para decidir: «si» y «si no» |
| sangría | espacios al inicio de una línea que indican qué depende de la línea anterior |
| error de lógica | error que el lenguaje entiende pero hace algo distinto de lo que se quería |

Problema: ¿Qué muestra P1, en orden?

Respuesta: 1, 2 y 3

Respuesta: 72: «Cumple»; 55: «No cumple»

**Errores frecuentes y cómo reconocerlos**

- **Error:** Olvidar los dos puntos después de while o if. **Por qué ocurre:** Es un error de sintaxis: el lenguaje no entiende la línea. **Cómo corregirlo:** Cierra la condición con dos puntos.
- **Error:** Escribir la sangría solo en la primera línea del bloque que se repite. **Por qué ocurre:** Las otras líneas quedan fuera del while y no se repiten. **Cómo corregirlo:** Todas las líneas que se repiten llevan la misma sangría.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Hoy aplicaré el proceso lógico completo, desde el problema hasta el código en Python seguido a mano, y cuidaré la honestidad al decir qué comprobé.

**Lo que ya debo saber.** Ya uso listas, tablas y números en mi vida diaria, como una boleta, un horario o un registro de gastos. Sé que un algoritmo es una secuencia de pasos claros para resolver un problema.

**Explicación.**

El proceso lógico que vincula un algoritmo con un lenguaje tiene seis pasos: entender el problema, identificar los datos de entrada y el resultado, escribir el seudocódigo, traducirlo a Python, seguir el código a mano con un caso y corregir los errores. Cada paso prepara el siguiente y evita saltarse la revisión.

Probar con varios casos es parte del proceso. Los casos límite, donde el valor queda justo en el borde de una condición, muestran errores como usar > en lugar de >=. En la ficha, con 10 familias el total es exactamente $20.000 y debe decir «Alcanza»; un programa con > diría «No alcanza» por error de lógica.

Actuar con ética es decir con honestidad lo que se comprobó: si no seguiste el código con casos, no afirmes que funciona. Si usas código escrito por otra persona, indica de quién es y revisa que haga lo que necesitas. Los comentarios con # ayudan a que otras personas entiendan tu trabajo.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| entrada y resultado | datos con que parte el programa y lo que debe informar |
| caso límite | caso en el borde de una condición, como el valor exacto de una meta |
| seguimiento a mano | revisar el código línea por línea anotando el valor de las variables |
| crédito | reconocer de quién es un código o una idea |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Seguir el programa de la ficha*

Problema: ¿Qué muestra el programa con 12 familias?

1. total = 2000 × 12 = 24000.
2. 24000 ≥ 20000 es verdadero y se ejecuta el if.

Respuesta: Alcanza

*Ejemplo 2. Encontrar un error de lógica*

Problema: Con una cuota de $3.000, una meta de $18.000 y 6 familias, un programa con if total > 18000 dice «No alcanza». ¿Qué falla?

1. Con 6 familias total = 18000.
2. 18000 > 18000 es falso, pero 18000 sí alcanza la meta.
3. Debe usarse >=.

Respuesta: Debe usar >= en lugar de >

**Errores frecuentes y cómo reconocerlos**

- **Error:** Probar el programa con un solo caso. **Por qué ocurre:** Un caso común no revela errores en el borde de la condición. **Cómo corregirlo:** Prueba también un caso límite, como el valor exacto de la meta.
- **Error:** Decir que el programa «funciona perfecto» sin haberlo seguido a mano. **Por qué ocurre:** No hay evidencia de lo que se comprobó. **Cómo corregirlo:** Sigue al menos dos casos y afirma solo lo que probaste.
