### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a escribir y seguir a mano algoritmos con repeticiones (for y while) que ejecutan un procedimiento matemático, como sumar una serie de números.

**Lo que ya debo saber.** Sé qué es una variable y una condición. Sé sumar y multiplicar números enteros. Sé que un programa se ejecuta línea por línea.

**Explicación.**

Un algoritmo es una secuencia finita de pasos precisos que realiza un procedimiento. Para un procedimiento matemático, como sumar 1 + 2 + 3 + 4, se define el valor inicial de un acumulador (suma = 0), qué valores se recorren y qué se hace en cada vuelta. El for repite un bloque una cantidad conocida de veces; el while lo repite mientras una condición sea verdadera.

range(1, 5) entrega 1, 2, 3 y 4: incluye el primer número y excluye el último. Por eso para sumar hasta 10 se escribe range(1, 11). Con range(2, 11, 2) se recorren 2, 4, 6, 8 y 10, porque el tercer número es el paso. Un error común es olvidar iniciar el acumulador en 0 o escribir mal el final del rango.

Para comprobar un algoritmo se sigue paso a paso en una tabla de seguimiento (traza), con una columna por variable y una fila por vuelta. En un while hay que asegurarse de que algo cambie dentro del bloque que haga falsa la condición; si no, el bucle nunca termina. Por ejemplo, en el programa B la línea n = n - 1 es la que permite que termine.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| algoritmo | secuencia finita de pasos precisos |
| acumulador | variable que va guardando un total |
| for | bucle que repite para cada valor de un rango |
| while | bucle que repite mientras la condición sea verdadera |
| traza | seguimiento paso a paso de los valores de las variables |
| bucle infinito | repetición que nunca termina |

1. Inicia suma = 0 y usa range(2, 11, 2), que recorre 2, 4, 6, 8 y 10.
2. Se suma 2 + 4 + 6 + 8 + 10.

Respuesta: El resultado es 30

**Errores frecuentes y cómo reconocerlos**

- **Error:** Creer que range(1, 5) incluye el 5. **Por qué ocurre:** El final del rango se excluye. **Cómo corregirlo:** Para llegar hasta n escribe range(1, n + 1).
- **Error:** No iniciar el acumulador en 0 antes del for. **Por qué ocurre:** La variable no existe o tiene un valor viejo, y la suma sale mal. **Cómo corregirlo:** Escribe suma = 0 antes de empezar a sumar.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a representar un mismo algoritmo de dos maneras, en pseudocódigo y en una tabla de seguimiento, y a ejecutarlo a mano para calcular un máximo común divisor.

**Lo que ya debo saber.** Sé qué es un divisor y un múltiplo. Sé usar el resto de una división. Sé seguir un while a mano.

**Explicación.**

El mismo algoritmo se puede representar de varias maneras. El pseudocódigo describe los pasos con palabras cercanas al lenguaje natural, sin las reglas estrictas de un lenguaje; el código en Python los escribe con esas reglas; y la tabla de seguimiento (traza) muestra los valores concretos de las variables en cada vuelta para un caso. Cada representación sirve para algo distinto: describir, ejecutar y comprobar.

El máximo común divisor de dos números es el mayor número que divide a ambos. El algoritmo de Euclides se basa en que mcd(a, b) es igual a mcd(b, resto de a dividido por b). Se repite hasta que b vale 0, y entonces el mcd es a. Por ejemplo, con 12 y 8: el resto de 12 dividido por 8 es 4, luego se continúa con 8 y 4; el resto es 0, y el mcd es 4.

El algoritmo siempre termina porque el resto es menor que b: en cada vuelta b disminuye, y como es un entero no negativo, tarde o temprano llega a 0. Aunque a sea menor que b, la primera vuelta los intercambia: el resto de 5 dividido por 15 es 5, y se continúa con 15 y 5. Para verificar el resultado se pueden listar los divisores de cada número y comprobar que el mayor común coincide.

| Palabra | Qué significa |

| resto | lo que sobra al dividir |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Tabla de seguimiento*

Problema: Sigue el algoritmo con a = 12 y b = 8.

1. Vuelta 1: resto = 12 % 8 = 4; ahora a = 8 y b = 4.
2. Vuelta 2: resto = 8 % 4 = 0; ahora a = 4 y b = 0. Como b es 0, termina.

Respuesta: El mcd es 4

*Ejemplo 2. Verificar con divisores*

Problema: Calcula el mcd de 30 y 18 y verifícalo listando divisores.

1. Euclides: 30 % 18 = 12; 18 % 12 = 6; 12 % 6 = 0. El mcd es 6.
2. Divisores de 30: 1, 2, 3, 5, 6, 10, 15, 30. De 18: 1, 2, 3, 6, 9, 18. El mayor común es 6.

Respuesta: mcd(30, 18) = 6, y coincide con los divisores

**Errores frecuentes y cómo reconocerlos**

- **Error:** Usar la división entera // en vez de % para el resto. **Por qué ocurre:** // entrega el cociente, no lo que sobra. **Cómo corregirlo:** Para el resto usa %.
- **Error:** Imprimir b al terminar el algoritmo. **Por qué ocurre:** Cuando el while termina, b vale 0 y el mcd quedó guardado en a. **Cómo corregirlo:** Al final del while, imprime a.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a obtener los términos de una sucesión definida por una regla o patrón, con una fórmula y con un programa, y a elegir el método que conviene.

**Lo que ya debo saber.** Sé qué es una sucesión de números. Sé escribir listas y recorrerlas con un for. Sé reemplazar una letra por un valor en una fórmula.

**Explicación.**

Una sucesión es una lista ordenada de números llamados términos. Puede definirse con una regla explícita, que da el término de la posición n directamente (por ejemplo t(n) = 5·n − 3), o con una regla recursiva, que indica el primer término y cómo obtener cada término a partir del anterior. Con la fórmula, t(1) = 2, t(2) = 7 y t(3) = 12; con la regla recursiva se obtienen los mismos números sumando 5 cada vez.

Para programar una sucesión se escribe un bucle: se parte con el primer término, se agrega a una lista y se actualiza con la regla. Si cantidad vale 4, el programa de la ficha entrega [2, 7, 12, 17]. Hay que cuidar el número de vueltas: range(4) da cuatro términos, no los términos hasta el 4. Una regla de multiplicar por una constante, como duplicar, produce una sucesión que crece más rápido.

Cada método tiene su ventaja. La fórmula explícita permite calcular un término lejano sin los anteriores: t(500) = 5 · 500 − 3 = 2.497. La regla recursiva es más fácil de programar cuando se conoce el paso entre términos. Para reconocer un patrón se miran las diferencias entre términos consecutivos: si son constantes, se suma siempre lo mismo; si no lo son, la regla es otra. También hay sucesiones donde cada término depende de los dos anteriores, como 1, 1, 2, 3, 5, 8…

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| sucesión | lista ordenada de números llamados términos |
| término | cada número de la sucesión |
| regla explícita | fórmula que da el término n directamente |
| regla recursiva | indica el primer término y cómo pasar al siguiente |
| diferencia | resta entre términos consecutivos |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Término lejano*

Problema: Con la regla explícita de la ficha, ¿cuánto vale t(20)?

1. Reemplaza n por 20: 5 · 20 − 3.
2. 5 · 20 = 100 y 100 − 3 = 97.

Respuesta: t(20) = 97

*Ejemplo 2. Regla recursiva*

Problema: ¿Cuál es el 6.º término de 3, 6, 12, 24, … si cada término es el doble del anterior?

1. Sigue duplicando: 24 · 2 = 48 y 48 · 2 = 96.
2. Los términos son 3, 6, 12, 24, 48 y 96.

Respuesta: El 6.º término es 96

**Errores frecuentes y cómo reconocerlos**

- **Error:** Confundir el número del término con su valor, por ejemplo decir que t(3) = 3. **Por qué ocurre:** n indica la posición; el valor lo da la regla. **Cómo corregirlo:** Reemplaza n en la fórmula y calcula.
- **Error:** Creer que range(4) genera los términos hasta el 4. **Por qué ocurre:** range(4) hace cuatro vueltas y por tanto genera cuatro términos. **Cómo corregirlo:** Cuenta las vueltas, no el valor del último término.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a justificar por qué un algoritmo es correcto y a comparar dos algoritmos para el mismo problema contando sus operaciones.

**Lo que ya debo saber.** Sé que un primo tiene solo dos divisores. Sé usar % para saber si un número divide a otro. Sé seguir un for y un while a mano.

**Explicación.**

Dos algoritmos pueden dar siempre la misma respuesta y aun así hacer muy distinta cantidad de trabajo. Para comparar se cuenta cuántas veces se repite la operación principal, aquí n % d. El programa 1 prueba todos los divisores de 2 a n − 1; el programa 2 prueba solo mientras d · d ≤ n. Para n = 97, que es primo, el programa 1 revisa 95 valores y el programa 2 revisa solo 8.

El programa 2 funciona porque, si n = a · b con a ≤ b, entonces a · a ≤ n. Por eso, si n es compuesto (tiene algún divisor distinto de 1 y de n), tiene alguno que no supera la raíz cuadrada de n (el número que multiplicado por sí mismo da n), y basta probar hasta d · d ≤ n. El detalle importa: si se escribiera d · d < n, primo2(9) devolvería True aunque 9 = 3 · 3 no es primo, porque no probaría d = 3. Los errores en los bordes son típicos.

Justificar un algoritmo significa explicar por qué da la respuesta correcta y por qué termina. En el programa 2, d aumenta de a uno, así que el while termina; y cada vez que continúa se sabe que ningún d probado dividió a n. Un algoritmo más eficiente puede ser más difícil de entender, y por eso se justifica con un argumento y se prueba con casos, incluidos 2, 4 y los cuadrados de primos.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| número primo | número mayor que 1 con solo dos divisores: 1 y él mismo |
| eficiencia | cantidad de trabajo que hace un algoritmo |
| operación principal | paso que más se repite y que se cuenta |
| caso borde | valor justo en el límite de una condición |
| justificar | explicar con argumentos por qué algo es correcto |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Contar operaciones*

Problema: Para n = 13 (primo), ¿cuántas veces calcula n % d cada programa?

1. primo1 prueba d = 2, 3, … 12: son 11 valores.
2. primo2 prueba d = 2 y d = 3; con d = 4, 16 > 13 y se detiene: 2 valores.

Respuesta: primo1 hace 11 cálculos y primo2 hace 2

*Ejemplo 2. Un caso borde*

Problema: ¿Qué devuelve primo2(9)?

1. d = 2: 4 <= 9 y 9 % 2 = 1, así que sigue con d = 3.
2. d = 3: 9 <= 9 se cumple y 9 % 3 = 0, por lo que devuelve False.

Respuesta: Devuelve False, porque 9 = 3 · 3 no es primo

**Errores frecuentes y cómo reconocerlos**

- **Error:** Escribir d * d < n en vez de d * d <= n. **Por qué ocurre:** Deja de probar justo en el divisor que es la raíz exacta, como el 3 en 9. **Cómo corregirlo:** Prueba el programa con cuadrados de primos, como 9, 25 o 49.
- **Error:** Creer que primo1 falla con n = 2 porque range(2, 2) está vacío. **Por qué ocurre:** El for no se ejecuta y la función llega a return True, que es correcto. **Cómo corregirlo:** Sigue el programa a mano con los casos más pequeños.

**Solucionario razonado**

- **R1.** A) False. Con d = 3, 15 % 3 es 0 y devuelve False; 3 es el divisor encontrado, no el resultado.

- **D1.** A) Si n = a · b con a ≤ b, entonces a · a ≤ n: todo número compuesto tiene un divisor no mayor que su raíz. Si un divisor a es el menor de los dos factores, su cuadrado no supera a n.
- **D2.** primo2(2) devuelve True y primo2(4) devuelve False. Para 2 el while no se ejecuta (4 > 2) y devuelve True; para 4, d = 2 cumple 4 <= 4 y 4 % 2 = 0.
- **S1.** B) 10. 10 · 10 = 100 <= 101, pero 11 · 11 = 121 supera a 101, así que el último d es 10.
- **E1.** Dos: 1 y él mismo. Esa es la definición de número primo.
- **E2.** Termina la función y entrega un valor. Las líneas que siguen a un return ejecutado ya no se leen.
- **E3.** Para comparar su eficiencia con la de otro. Menos operaciones para la misma respuesta indica un algoritmo más eficiente.
