### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a abstraer un problema: decidir qué datos son entrada y salida, qué condiciones importan y qué detalles se pueden ignorar, y a seguir un programa breve a mano.

**Lo que ya debo saber.** Sé que un programa recibe datos, los procesa y entrega un resultado. Sé resolver porcentajes simples con números enteros. Sé leer una condición del tipo «si… entonces…».

**Explicación.**

Abstraer es quedarse con lo esencial de un problema y dejar fuera los detalles que no cambian el resultado. Para programar, primero se precisan las entradas (los datos que recibe), la salida (lo que entrega) y las condiciones (reglas del tipo «si el monto es 20.000 o más»). Cada dato tiene un tipo: entero, texto o booleano (verdadero o falso). Una comparación como monto >= 20000 produce un booleano.

Una función es un bloque de código con nombre; sus parámetros son las entradas, como monto, y return entrega la salida. Una variable es un nombre que guarda un valor, y el signo = asigna: monto = 20000 no pregunta nada, solo guarda el valor. Para preguntar si dos valores son iguales se usa ==. El orden importa: cuando una línea return se ejecuta, la función termina y las líneas que siguen ya no se leen.

Para comprobar una función se sigue a mano con un caso concreto y se anota qué vale cada variable. Una buena abstracción incluye todo lo necesario y nada más: si el programa pide un dato que no cambia el resultado, sobra; si le falta uno que sí lo cambia, el resultado será incorrecto. También se revisa qué pasa justo en el límite de una condición, por ejemplo con un monto de exactamente 20.000.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| abstracción | quedarse con lo esencial y dejar fuera los detalles |
| entrada | dato que recibe un programa |
| salida | resultado que entrega |
| variable | nombre que guarda un valor |
| función | bloque de código con nombre, parámetros y un valor de retorno |
| booleano | valor verdadero o falso |
| condición | pregunta que decide qué camino sigue el programa |

**Errores frecuentes y cómo reconocerlos**

- **Error:** Pedir como entrada un dato que no cambia el resultado, como el nombre de la tienda. **Por qué ocurre:** Los detalles irrelevantes complican el programa sin aportar nada. **Cómo corregirlo:** Pregunta de cada dato: «¿cambia la salida si lo cambio?».
- **Error:** Escribir monto = 20000 para preguntar si el monto vale 20000. **Por qué ocurre:** En Python, = guarda un valor; para comparar se usa ==. **Cómo corregirlo:** Usa == para igualdad y >= o > para mayor o igual y mayor.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a organizar datos en listas y diccionarios, a representar los mismos datos de dos maneras y a elegir la organización que conviene según la pregunta.

**Lo que ya debo saber.** Sé qué es una variable y un bucle for. Sé calcular un promedio con la división entera. Sé leer una tabla de dos columnas.

**Explicación.**

Organizar los datos de forma lógica significa elegir una estructura que permita responder la pregunta con pocos pasos. Una lista guarda valores en orden y cada uno tiene un índice que parte en 0: en una lista de 4 elementos los índices son 0, 1, 2 y 3. La función len entrega la cantidad de elementos, y el último índice vale len menos 1. Leer una posición que no existe produce un error.

Un diccionario asocia una clave con un valor: la clave sirve para consultar sin recordar la posición. La lista conviene cuando importa el orden o se recorre todo; el diccionario conviene cuando se consulta por un nombre o un código. Los mismos datos se pueden representar de dos maneras, por ejemplo como lista de notas y como diccionario nombre-nota, y cada una responde mejor ciertas preguntas.

Para recorrer una lista se usa for n in lista, que entrega cada elemento una vez. Con una variable acumuladora se calcula una suma, y dividiéndola por len se obtiene el promedio. Para estructuras más ricas se combinan: un diccionario por estudiante, con claves como «nombre» y «notas», donde notas es a su vez una lista. Siempre se comprueba con un caso pequeño que la organización permite leer el dato buscado.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| lista | colección ordenada de valores |
| índice | posición de un elemento, que parte en 0 |
| diccionario | colección de pares clave-valor |
| clave | nombre con que se consulta un valor |
| recorrer | pasar por cada elemento de una lista |
| acumulador | variable que va sumando valores |

**Errores frecuentes y cómo reconocerlos**

- **Error:** Contar las posiciones desde 1 y escribir notas[4] para el cuarto elemento. **Por qué ocurre:** El primer índice es 0; el cuarto elemento es notas[3]. **Cómo corregirlo:** Con n elementos, los índices van de 0 a n − 1.
- **Error:** Creer que el último índice es len(lista). **Por qué ocurre:** len entrega la cantidad de elementos, que es una unidad mayor que el último índice. **Cómo corregirlo:** Usa lista[len(lista) - 1] para el último elemento.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a analizar dos soluciones alternativas para el mismo problema, a contar sus comparaciones y a decidir cuál conviene según las condiciones.

**Lo que ya debo saber.** Sé recorrer una lista con un índice. Sé usar la división entera y las condiciones. Sé que una lista puede estar ordenada.

**Explicación.**

Un mismo problema puede tener varias soluciones correctas. Para elegir entre ellas se comparan criterios: cuántos pasos hacen, qué condiciones previas exigen y qué tan simples son. Buscar un valor en una lista se puede hacer de a un valor desde el inicio (solución A) o, si la lista está ordenada, mirando el valor del medio y descartando la mitad (solución B, llamada búsqueda binaria).

La solución A funciona con cualquier lista, pero en el peor caso mira todos los valores. La solución B exige que la lista esté ordenada, y a cambio reduce el tramo a casi la mitad en cada comparación. Con 7 valores hace como máximo 3 comparaciones; con 1.000 valores, unas 10. Si la lista no está ordenada, B puede decir que un valor no está aunque sí esté.

Analizar alternativas incluye considerar el costo previo de ordenar la lista: ordenar una lista también toma trabajo, y si la lista cambia a diario o se consulta pocas veces, puede no compensar. Ninguna solución es mejor en todos los casos: para el primer valor de la lista A gana, para el último B gana. Se decide con datos: contar pasos en casos típicos y extremos.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| búsqueda secuencial | revisar los valores de a uno en orden |
| búsqueda binaria | mirar el medio de una lista ordenada y descartar la mitad |
| comparación | una revisión de un valor de la lista |
| peor caso | la entrada que obliga a hacer más pasos |
| precondición | condición que debe cumplirse antes de usar el algoritmo |

**Ejemplos resueltos paso a paso**

*Ejemplo 1. Contar comparaciones*

Problema: En la lista de la ficha, ¿cuántas comparaciones hacen A y B para encontrar el 8?

1. A revisa 3 y 8: son 2 comparaciones.
2. B mira medio = 3 (valor 17); como 8 < 17, el tramo es 0..2; medio = 1 (valor 8): 2 comparaciones.

Respuesta: A y B hacen 2 comparaciones cada una

*Ejemplo 2. Una precondición que falla*

Problema: La lista [17, 3, 30, 8] no está ordenada. ¿Qué concluye B al buscar el 8?

1. Con inicio = 0 y fin = 3, medio = 1 (valor 3); como 8 > 3, el tramo es 2..3.
2. Entonces medio = 2 (valor 30); como 8 < 30, fin = 1 y el tramo queda vacío.

Respuesta: B concluye que el 8 no está, aunque sí está en la posición 3

**Errores frecuentes y cómo reconocerlos**

- **Error:** Afirmar que B es siempre más rápida que A. **Por qué ocurre:** Para un valor cercano al inicio, A termina antes que B. **Cómo corregirlo:** Compara con casos concretos antes de decidir.
- **Error:** Usar B en una lista que no está ordenada. **Por qué ocurre:** B descarta mitades suponiendo el orden; sin orden puede descartar donde está el valor. **Cómo corregirlo:** Revisa la precondición del algoritmo antes de aplicarlo.

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a generalizar: pasar de un caso particular a una función con parámetros, reconocer el patrón que se repite y justificar hasta dónde sirve la solución general.

**Lo que ya debo saber.** Sé usar la división entera y el resto. Sé escribir una función con parámetros. Sé reconocer qué cambia y qué se repite en varios cálculos parecidos.

**Explicación.**

Generalizar es reemplazar los valores fijos de un caso particular por parámetros, de modo que la misma solución sirva para muchos casos. Primero se comparan varios casos parecidos y se detecta qué cambia (los datos) y qué se repite (el patrón). Lo que cambia pasa a ser un parámetro; lo que se repite queda en el cuerpo de la función.

Una función general se escribe una vez y se reutiliza: empacar(100, 8) y empacar(50, 6) usan el mismo código. Se justifica comprobándola con los casos particulares que le dieron origen y con otros nuevos. Un error frecuente es dejar un número fijo dentro de la función general, como escribir 6 en vez de por_caja, porque entonces solo sirve para ese caso.

Toda generalización tiene límites que hay que prever. Si por_caja vale 0, la división falla; si total es menor que por_caja, el resultado es 0 cajas con todo sobrante, lo cual es correcto. Por eso se agregan condiciones o validaciones. También se generaliza un patrón de números: si las figuras tienen 4, 7, 10… palitos y cada una agrega 3, la regla general es 3·n + 1 para la figura n.

| Palabra | Qué significa |
|---|---|
| generalizar | pasar de casos particulares a una solución válida para muchos |
| parámetro | dato que cambia y se pasa a la función |
| patrón | regularidad que se repite entre casos |
| cociente | resultado de una división entera |
| resto | lo que sobra en una división entera |
| validación | comprobación de que un dato es aceptable |

### Cuaderno del estudiante

**Lo que aprenderé y para qué sirve.** Aprenderé a comprobar una solución con casos de prueba (típicos y límite), a encontrar un contraejemplo y a comparar dos soluciones solo después de comprobar que son correctas.

**Lo que ya debo saber.** Sé seguir una función a mano. Sé usar condiciones con and. Sé que una solución puede tener errores aunque pase algunas pruebas.

**Explicación.**

Comprobar una solución es probarla con casos cuyo resultado correcto ya se conoce. Un buen juego de pruebas incluye casos típicos (que ejercitan cada rama, es decir, cada camino posible del programa), casos límite (empates, ceros, valores negativos, extremos) y casos donde la respuesta esté en cada posición posible. Si una prueba da un resultado distinto del esperado, se encontró un contraejemplo: eso demuestra que hay un error.

Pasar varias pruebas no demuestra que un programa sea correcto; solo aumenta la confianza. Un único contraejemplo, en cambio, basta para refutarlo. Por eso se buscan activamente los casos que podrían fallar. En mayor2, por ejemplo, cuando a > b devuelve a sin comparar con c, y eso falla si c es el mayor.

Solo se comparan soluciones que han pasado la comprobación. Una solución más corta o con menos comparaciones no es mejor si da resultados incorrectos. Entre soluciones correctas se comparan la cantidad de pasos, la claridad y qué tan fácil es de modificar. La conclusión siempre debe apoyarse en los casos probados, no en la impresión.

**Palabras importantes**

| Palabra | Qué significa |
|---|---|
| rama | cada camino posible dentro de un programa, por ejemplo cada return |
| caso de prueba | entrada con el resultado esperado conocido |
| caso límite | entrada extrema o especial, como un empate o un cero |
| contraejemplo | caso que muestra que una solución falla |
| correcta | que da el resultado esperado en todos los casos |
| comparar | contrastar soluciones por pasos, claridad y facilidad de cambio |

*Autoevaluación*

- **E1.** En Pensamiento computacional: ¿qué es un caso límite?
- **E2.** En Pensamiento computacional: ¿qué muestra un contraejemplo?
- **E3.** ¿Basta con que pasen tres pruebas para asegurar que un programa es correcto?

**Actividad abierta.** Esta función debería devolver el menor de tres enteros: def menor(a, b, c): ↵ ··if a < b: ↵ ····return a ↵ ··if b < c: ↵ ····return b ↵ ··return c. Arma una tabla de seis pruebas con el resultado esperado y el que entrega la función (con el menor en cada posición, un empate y un caso con negativos), encuentra un contraejemplo, corrígela y escribe una conclusión.

**Solucionario razonado**

- **R1.** A) 9. La primera condición falla porque 4 no es mayor o igual que 9; luego b >= c es 9 >= 6, verdadero, y devuelve b.
- **R2.** A) 8. a > b es falso; b > c es verdadero (8 > 5) y devuelve b.
- **R3.** A) Que hay un error en el programa (o en lo que se esperaba). Un resultado distinto del esperado es un contraejemplo y obliga a revisar el programa.
- **C1.** A) (6, 2, 8). Con (6, 2, 8) devuelve 6 porque 6 > 2, pero el mayor es 8; las otras dos entradas dan el resultado correcto.
- **C2.** Devuelve 9; lo correcto es 12. Como 9 > 4 devuelve a sin mirar c, que es mayor.
- **C3.** A) Porque ninguna de las dos condiciones se cumple y llega a return c, que vale 9. a > b y b > c son falsas, así que se ejecuta el return final, que entrega c.
- **A1.** 7. a >= b y a >= c son verdaderas (7 >= 7 y 7 >= 1), así que devuelve a.
- **A2.** A) −3. Entre los negativos el mayor es el más cercano a cero; la primera condición falla (−6 < −3) y b >= c (−3 >= −9) devuelve −3.
- **A3.** C) Un caso con el mayor en cada posición, un empate y uno con negativos. Un buen juego de pruebas ejercita todas las ramas y los casos límite, no solo una.
- **Z1.** A) Que pasar pruebas no demuestra corrección: la entrada (6, 2, 8) la refuta. Ninguna cantidad de pruebas que pasan demuestra corrección, pero un solo contraejemplo la refuta.
- **Z2.** A) Cuando a > b devuelve a sin compararlo con c. Con a > b verdadero ya no revisa c; los empates los resuelve bien, como en (7, 7, 1).
- **D1.** A) No es buena razón: mayor2 es incorrecta, y una solución incorrecta no se compara por velocidad. Primero se comprueba que sea correcta; solo entre soluciones correctas se compara la eficiencia.
- **D2.** A) (2, 1, 3). Con (2, 1, 3) se cumple a > b, devuelve 2 y el mayor es 3; las otras cinco ordenaciones dan el resultado correcto.
- **S1.** B) 55. a >= b y a >= c se cumplen (55 >= 55 y 55 >= 40), y el empate se resuelve bien devolviendo 55.
- **E1.** Una entrada extrema o especial, como un empate o un cero, donde suelen aparecer errores. Ahí se prueban los bordes de las condiciones, donde fallan más los programas.
- **E2.** Que la solución tiene un error. Un solo caso que falla basta para refutar una solución.
- **E3.** No. Pasar pruebas aumenta la confianza, pero no demuestra corrección general.

**Actividad abierta · ejemplo de respuesta.** Con (5, 9, 2) la función devuelve 5 porque 5 < 9, pero el menor es 2: es un contraejemplo. Una corrección es if a <= b and a <= c: return a, luego if b <= c: return b, y por último return c.

**Criterios para evaluarla:** arma seis pruebas variadas; identifica un contraejemplo concreto; propone y prueba una corrección.

**Evidencias aceptables:** tabla de pruebas, el contraejemplo y la versión corregida.

**Errores que conviene detectar:** probar solo casos con el menor al inicio; no anotar el resultado esperado antes de seguir el código; corregir sin volver a probar.

**Retroalimentación constructiva:** Pregunta: «¿qué resultado esperabas antes de seguir el código?». Si no lo tenía, pídele que lo calcule primero.

**Refuerzo.** Sigue a mano mayor1 y mayor2 con (3, 5, 5) y (8, 8, 8) y anota si los resultados coinciden.

**Profundización.** Explica por qué en una comparación entre soluciones se verifica primero la corrección y solo después la eficiencia.


**Apoyo en el mismo OA:** Reduce cantidad de datos, ofrece una representación equivalente y una lista de condiciones; conserva la decisión matemática y no completa el procedimiento.

**Profundización:** Cambia un parámetro, restricción o representación, formula una conjetura y determina si el argumento todavía se sostiene.

**Evidencia:** Resolución matemática individual de «comprobar y comparar: aplicar conceptos de ciencias de la computación -abstracción, organización lógica de…» con representación, estrategia, justificación, interpretación y comprobación.

**Criterios de éxito:** desarrolla «comprobar y comparar: aplicar conceptos de ciencias de la computación -abstracción, organización lógica de…» en el caso propuesto; usa una decisión y evidencia propias de la disciplina; explica el alcance, revisa un error o reconoce una limitación.

**Decisión posterior:** Avanza cuando decisión, evidencia y explicación coinciden; si no, localiza la barrera, modela otro caso y recoge una nueva evidencia sin etiquetar a la persona.

**Adaptación a 45 minutos:** Conserva el caso específico, modelado breve, práctica guiada, evidencia individual y ticket; reduce cantidad o turnos, no la demanda del OA.

**Tarea breve y flexible:** Observa, representa o explica un caso seguro con recursos disponibles. No requiere compras, internet ni revelar datos personales, familiares, corporales o políticos.

**Actividades complementarias (opcionales):**
- Recuperación: reduce variables o elementos y vuelve después al desafío completo.
- Análisis de error: revisa un caso ficticio que muestra esta confusión: aceptar un resultado sin interpretarlo ni verificarlo.
- Transferencia: cambia contexto, fuente, audiencia, escala o restricción y revisa la decisión.

**Control de dificultades en el aula**

| Dificultad observable | Acción inmediata | Cómo comprobar si funcionó |
|---|---|---|
| Responde antes de examinar el caso o la evidencia | Pide localizar primero el dato, rasgo, fuente, criterio o condición que utilizará. | La nueva respuesta cita una evidencia pertinente. |
| Aceptar un resultado sin interpretarlo ni verificarlo | Reduce cantidad de datos, ofrece una representación equivalente y una lista de condiciones; conserva la decisión matemática y no completa el procedimiento. | Resuelve un caso nuevo sin repetir la confusión y explica la diferencia. |
| Completa la actividad, pero no justifica su decisión | Solicita comparar con una alternativa y nombrar el criterio decisivo. | La explicación permite reconstruir y revisar la decisión. |

**Coordinación de roles profesionales:** El docente mantiene lenguaje y demanda matemática; los apoyos de acceso no sustituyen representación, razonamiento ni comprobación individual.

## Evaluación integradora y realidad escolar
Evalúa contenido, respuesta al verbo, evidencia o razonamiento y comunicación/revisión. Registra evidencia individual. Considera diversidad lingüística, cultural, sensorial y motriz.
